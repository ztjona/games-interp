# BSP Set Comparison: Gorilla, Hawk, and Tiger

Supervisor advance -- May 2026.

## Overview

Three BSP (Board State Property) sets probe different axes of what a Quarto neural network has learned. Each set is evaluated independently against SAE features; they are **alternative bases**, not cumulative layers.

| Property | **Gorilla** (164 BSPs) | **Hawk** (173 BSPs) | **Tiger** (36 BSPs) |
|---|---|---|---|
| Axis | Raw game state | Reframed threats | Agent-relative decisions |
| Core question | "What is on the board?" | "Where are threats and can they be completed?" | "What should the agent do about it?" |
| Perspective | Objective (third-person) | Objective (third-person) | First-person (agent-relative) |
| Inspiration | Ground-truth game rules | Nanda et al. (MINE/YOURS reframing from OthelloGPT) | Model competence audit: champTa's +24 pp loss-avoidance gain implies agent-relative representations |
| Introduced | Phase 1 (2026-03) | Phase 1E (2026-04) | Phase 2B (2026-05-22) |

## What Tiger adds that Gorilla/Hawk cannot express

| Concept | Tiger category | Why absent from Gorilla/Hawk |
|---|---|---|
| "Can I win right now on this specific line/square?" | `tiger_line_winnable`, `tiger_square_winnable` | Gorilla/Hawk encode threat existence but not that the offered piece resolves it at a specific cell |
| "How poisoned is the pool of pieces I can offer?" | `tiger_pool_winning_count` | Requires reasoning over unplaced pieces -- outside the board-state axis entirely |
| "Do I have any safe offering option?" | `tiger_pool_safe_count` | Same: pool-level reasoning, not board-level |
| "Am I forced to lose next turn?" | `tiger_decision_global` | Requires exhaustive check over all pool pieces; no single board property captures this |
| "Which attribute makes the offered piece a winning completer?" | `tiger_offered_completing_attr` | Hawk's `completable` is per-line; tiger decomposes by which attribute does the work |

# Anchored SAE: I04-champVe-lh100-s42

Run ID: `I04-champVe-lh100-s42-anchored-jumprelu-t64-exp8-s4.fc1`

## What is an anchored SAE?

A standard SAE learns dictionary features purely from reconstruction loss -- features emerge unsupervised and may or may not align with human-defined concepts (BSPs). An **anchored SAE** reserves a prefix of dictionary slots and adds a BCE (binary cross-entropy) supervision loss on their encoder pre-activations, steering those slots to fire in alignment with specific BSP labels. The remaining slots train normally (unsupervised). This is a logistic probe embedded inside the SAE encoder.

## JumpReLU SAE -- mathematical definition

Reference: Rajamanoharan et al. 2024b.

### Encoder

The encoder computes a pre-activation vector and applies a hard threshold with learnable per-feature thresholds:

```
z = W_enc * (x - b_dec) + b_enc
h_i = z_i * 1[z_i > theta_i]
```

where `theta_i > 0` is a learnable threshold for feature `i`, parameterised in log-space (`theta_i = exp(log_theta_i)`) to enforce positivity. The `1[.]` is the Heaviside step function (JumpReLU activation).

### Decoder

```
x_hat = W_dec * h + b_dec
```

Decoder columns are unit-normalized after every optimizer step.

### Loss function

The total JumpReLU loss has two terms:

```
L = L_reconstruct + w * L_sparsity
```

| Term | Formula | Role |
|---|---|---|
| Reconstruction | `L_reconstruct = mean_B( \|\| x - x_hat \|\|^2 )` | Faithful activation reconstruction |
| Sparsity | `L_sparsity = (L0_approx - L0_target)^2` | Penalizes deviation from target active features |
| Weight | `w = 0.01` (l0_weight) | Balances sparsity vs reconstruction |

### Differentiable L0 approximation

The true L0 (`sum_i 1[h_i > 0]`) has zero gradient w.r.t. `theta`. The paper uses a sigmoid kernel estimator as a smooth proxy:

```
L0_approx = sum_i sigmoid((z_i - theta_i) / epsilon)
```

where `epsilon` (bandwidth) = 0.001. This provides gradient signal to push thresholds up or down toward the L0 target.

### Straight-Through Estimator (STE) paths

Two gradient paths coexist during training:

| Path | Forward pass | Backward pass | Trains |
|---|---|---|---|
| Reconstruction | Hard mask: `mask = 1[z > theta]` | Soft mask: `sigmoid((z - theta) / epsilon)` | `W_enc`, `b_enc`, `theta` toward better reconstruction |
| Sparsity | `L0_approx` via sigmoid | Direct gradient through sigmoid | `theta` toward L0 target |

The STE trick: `mask = mask_hard + (mask_soft - mask_soft.detach())`, which has the hard mask value in the forward pass but the soft mask gradient in the backward pass.

## Anchored JumpReLU -- additional loss term

The anchored variant adds a third term to the loss:

```
L_total = L_reconstruct + w * L_sparsity + L_anchor
```

### Anchor loss

For each anchored slot `k` (mapping dictionary feature `f_k` to BSP label `y_k`):

```
z = W_enc * (x - b_dec) + b_enc           (recomputed, clean autograd path)
L_anchor = mean_B( sum_k lambda_k * BCE(z_{f_k}, y_k) )
```

where `BCE` is binary cross-entropy with logits (numerically stable sigmoid + cross-entropy):

```
BCE(z, y) = -y * log(sigma(z)) - (1 - y) * log(1 - sigma(z))
```

and `lambda_k` is the per-anchor weight (1.0 for high-tier, 0.333 for medium-tier categories).

The anchor loss routes a smooth gradient directly through `W_enc` and `b_enc` for the anchored columns, making each anchored slot behave like a logistic regression probe embedded in the encoder. Crucially, `z` is recomputed from scratch (not reusing the JumpReLU's stashed `z`) to keep the autograd graph clean.

# Proposed unsupervised JumpReLU modifications

The anchored SAE achieves 85.6% SAE/LP efficiency on tiger, but requires labeled BSPs. Can we close the unsupervised SAE/LP gap without labels?

The current unsupervised JumpReLU (F04) has **90% dead features** -- only ~380 of 4096 dictionary slots are alive. This massive capacity waste is likely the primary bottleneck: the SAE cannot cover many BSP concepts because it doesn't have enough distinct features.

## Proposal: JumpReLU + Auxiliary Dead Feature Revival

**Source:** Inspired by Anthropic's ghost gradient technique and the auxiliary loss in Gated SAEs (Rajamanoharan et al. 2024a).

**Idea:** Add a secondary reconstruction loss that trains dead features to reconstruct the *residual error* left by the alive features. The dead/alive mask is **not learnable** -- it is a running statistic recomputed each batch from an exponential moving average (EMA) of activation frequency.

### Step 1: Standard JumpReLU forward pass (unchanged)

```
z = W_enc (x - b_dec) + b_enc
h_i = z_i * 1[z_i > theta_i]
x_hat = W_dec h + b_dec
```

### Step 2: Dead feature identification (non-differentiable running statistic)

Track each feature's activation frequency via an EMA updated after every batch:

```
freq_j <- (1 - gamma) * freq_j + gamma * (1/B) sum_b 1[h_j^(b) > 0]
```

| Symbol | Role | Typical value |
|---|---|---|
| `freq_j` | EMA of feature `j`'s firing rate | (running statistic, not a parameter) |
| `gamma` | EMA decay rate | 0.999 |
| `tau` | Dead threshold | 1e-5 |

Define the dead set and its binary mask:

```
D = { j : freq_j < tau }
mask_D_j = 1 if j in D, else 0
```

`mask_D` is **not a learnable parameter**. It is recomputed from the running `freq_j` statistics at each training step. Features transition in and out of the dead set as training progresses.

### Step 3: Auxiliary reconstruction through dead features

The key question: dead features have `h_j = 0` precisely because `z_j` never exceeds `theta_j`. If we use JumpReLU in the auxiliary path, we get zero activations and zero gradients -- defeating the purpose. Instead, the auxiliary path uses **plain ReLU** to bypass the thresholds:

```
e = (x - x_hat).detach()            -- residual error, detached from main computational graph
h_aux = ReLU(z) * mask_D             -- dead features only, ReLU bypasses theta
e_hat = h_aux @ W_dec                -- reconstruct residual (no bias: e is a residual, not a signal)
L_aux = ||e - e_hat||^2 / ||e||^2   -- normalized by residual magnitude
```

| Design choice | Rationale |
|---|---|
| `.detach()` on `e` | Auxiliary loss trains only dead features; does not backpropagate through alive features |
| ReLU instead of JumpReLU | Dead features are dead because `z_j < theta_j`; ReLU lets gradient flow to `W_enc` and `W_dec` despite the threshold |
| `mask_D` zeros alive features | Prevents competition with features that are already useful |
| No `b_dec` in `e_hat` | We are reconstructing a residual (error), not the original input |
| Normalization by `\|\|e\|\|^2` | Scales the auxiliary term relative to how much error remains, not the total signal magnitude |

### Step 4: Total loss

```
L = L_reconstruct + L_sparsity + L_aux
```

Expanded:

```
L = ||x - x_hat||^2 + w * (L0_approx - L0_target)^2 + alpha * ||e - e_hat||^2 / ||e||^2
```

| Term | Formula | Trains | Role |
|---|---|---|---|
| Reconstruction | `\|\|x - x_hat\|\|^2` | All alive features (`W_enc`, `W_dec`, `b_enc`, `b_dec`, `theta`) | Faithful activation reconstruction |
| Sparsity | `w * (L0_approx - L0_target)^2` | Thresholds `theta` (via sigmoid STE) | Target number of active features |
| Auxiliary revival | `alpha * \|\|e - e_hat\|\|^2 / \|\|e\|\|^2` | Dead features only (`W_enc` rows, `W_dec` columns for `j in D`) | Align dead features with residual structure |

### How revival works (gradient flow)

```
L_aux  -->  e_hat = h_aux @ W_dec
       -->  h_aux = ReLU(z) * mask_D
       -->  z = W_enc (x - b_dec) + b_enc
```

Gradients from `L_aux` flow to:

| Parameter | Effect |
|---|---|
| `W_enc[j, :]` for `j in D` | Rotates dead encoder rows to point toward directions that explain the residual |
| `W_dec[:, j]` for `j in D` | Rotates dead decoder columns to reconstruct the residual from the new activations |
| `b_enc[j]` for `j in D` | Shifts dead features' pre-activations toward positive values |
| `theta_j` for `j in D` | **No direct gradient** (ReLU bypasses theta). But once `W_enc[j]` points somewhere useful and `z_j` grows, `z_j` will exceed `theta_j` in the main path and the feature becomes alive naturally |

### Hyperparameters

| Parameter | Role | Suggested starting value |
|---|---|---|
| `alpha` | Weight of auxiliary loss relative to main reconstruction | 0.1 |
| `gamma` | EMA decay for frequency tracking | 0.999 |
| `tau` | Frequency threshold below which a feature is "dead" | 1e-5 |

### Diagnostic

The approach is working if:
- Dead feature percentage drops substantially (from 90% toward <50%)
- FVU remains at or below 0.004 (no reconstruction degradation)
- BSP coverage (F1-lift) improves on unsupervised runs without anchoring
